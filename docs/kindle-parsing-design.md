# Kindle 笔记解析与导出程序设计文档

## 1. 项目概述
本程序旨在解析 Kindle 导 la `My Clippings.txt` 文件，将其中的结构化数据提取出来，并实现“摘录内容”与“笔记内容”的智能关联合并，最终导出为易于管理的 `.csv` 格式文件。

## 2. 核心需求
- **输入**：`My Clippings.txt` (纯文本文件)。
- **输出**：`My Clippings.csv` (结构化表格文件)。
- **提取字段**：书名、摘录内容、笔记内容、日期时间、页码、位置。
- **核心逻辑**：
    - 必须将同一位置的“高亮摘录 (Highlight)”与“用户笔记 (Note)”合并到同一行。
    - **区间匹配**：如果笔记的位置数值介于摘录部分的起始位置与结束位置之间（含边界），则判定为同一条目并合并。
    - **清理机制**：程序运行之初，若当前目录下已存在 `My Clippings.csv`，则先将其删除，确保输出文件为本次解析的最新结果。
    - 处理摘录有笔记、摘录无笔记、仅有笔记等多种情况。
    - 确保大文本、多行内容不被错误截断。

## 3. 技术实现方案

### 3.1 解析架构：状态机 (State Machine)
为了应对 Kindle 文件的非标准格式（如内容包含换行），采用状态机解析法：

- **状态 [IDLE]** $\rightarrow$ 匹配非空行 $\rightarrow$ 提取 **书名** $\rightarrow$ 转移至 `[METADATA]`。
- **状态 [METADATA]** $\rightarrow$ 匹配 `- Your ...` 模式 $\rightarrow$ 提取 **类型(Highlight/Note/Bookmark)**、**页码**、**位置**、**时间** $\rightarrow$ 转移至 `[CONTENT]`。
- **状态 [CONTENT]** $\rightarrow$ 持续读取所有行直到遇到分隔符 `==========` $\rightarrow$ 合并所有行为 **正文内容** $\rightarrow$ 转移至 `[IDLE]`。

### 3.2 关联合并算法 (Merge Algorithm)

#### 3.2.1 位置区间判定逻辑
由于 Kindle 的高亮摘录通常显示为范围（如 `Location 200-220`），而笔记通常显示为单点（如 `Location 210`），程序将采用区间匹配而非字符串精确匹配：

1. **位置解析**：将所有位置字符串解析为数值区间 `(start, end)`。
    - 范围形式 (`200-220`) $\rightarrow$ `start=200, end=220`。
    - 单点形式 (`210`) $\rightarrow$ `start=210, end=210`。
2. **合并判定**：
    - 当解析到一条 `Note` 时，遍历当前书名下所有的 `Highlight` 记录。
    - 若 $\text{Highlight.start} \le \text{Note.location} \le \text{Highlight.end}$，则认为该笔记属于该摘录。
    - 将笔记内容合并至该摘录记录的 `note` 字段，并舍弃笔记本身的冗余元数据（日期、书名等）。

#### 3.2.2 存储与合并流程
- **临时存储**：使用列表记录所有解析出的原始条目，在导出前执行合并。
- **合并步骤**：
    1. 首先创建所有 `Highlight` 和 `Bookmark` 的基础记录。
    2. 遍历所有 `Note` 条目，通过上述区间判定逻辑，将笔记内容填充到对应的 Highlight 记录中。
    3. 未能匹配到任何 Highlight 的 Note 将作为独立记录保留。

### 3.3 CSV 导出配置
- **排序**：导出前对数据按 `(书名, 位置)` 进行升序排列。
- **表头定义**：`书名, 摘录内容, 笔记内容, 日期时间, 页码, 位置`。
- **编码格式**：使用 `utf-8-sig`。这是为了确保 Windows 系统下的 Excel 打开文件时不会出现中文乱码。
- **处理特殊字符**：使用 Python 内置的 `csv` 模块，自动处理内容中的逗号、双引号等特殊字符。

## 4. 鲁棒性设计
- **BOM 处理**：读取文件时使用 `utf-8-sig` 编码，自动处理文件开头的 UTF-8 BOM 标记。
- **容错解析**：
    - 使用正则表达式 $\text{`page\s+(\d+)}`$ 和 $\text{`Location\s+(\d+-\d+)}`$ 灵活提取位置，兼容不同 Kindle 版本的描述差异。
    - 对所有提取到的字符串执行 `.strip()` 去除冗余空格。
- **内存安全**：由于 `My Clippings.txt` 文件大小通常在可控范围内（<100MB），使用内存映射处理具有极高的性能且不会导致内存溢出。

## 5. 成功标准
- **正确性**：位置数值在范围内的笔记必须与对应的摘录合并在同一行。
- **完整性**：所有书籍的记录均被导出，无遗漏。
- **可用性**：导出的 CSV 文件可用 Excel 直接打开且无乱码。
